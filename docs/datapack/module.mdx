# Modules

## Description

Modules are the core of Truly Modular.They are stored in a Tree structure on the item.  Modules are split in 2 parts,### **The Item-Module**This is the raw from json loaded data from a datapack.This merely contains all the modules properties.It is simply a list of properties and their data, stored at the ID of the module.f.e. `tm_arsenal:miapi/modules/pommel/round.json` results in the id `tm_arsenal:pommel/round`and the lang keys of```    "miapi.module.tm_arsenal.pommel.round": "Round Pommel",    "miapi.module.tm_arsenal.pommel.round.name": "%s Round Pommel",    "miapi.module.tm_arsenal.pommel.round.description": "A spherical pommel that provides a balanced weight distribution and comfortable grip.",```Item-Modules are loaded from `namespace:miapi/modules/any-path-or-name.json`  Example Module-json from the round pommel of Arsenal.```json{    "model": {        "path": "miapi:models/item/sword/pommel/round/[material.texture].json",        "transform": {            "rotation": {"x": 0, "y": 0, "z": 0},            "translation": {"x": -4, "y": -5, "z": 0.001},            "scale": {"x": 1, "y": 1, "z": 1}        }    },    "allowed_in_slots": ["sword_pommel"],    "slots": {},    "attributes": [        {            "attribute": "generic.attack_speed",            "value": "0.10",            "operation": "+",            "slot": "mainhand"        }    ],    "priority": 0,    "repair_priority": 0,    "durability": "[material.durability]* 0.25",    "material_indication": {"durability": 1},    "allowed_material": {        "allowedMaterials": [            "wood", "metal", "flint", "bone",            "stone", "rod", "crystal", "glass"        ],        "cost": 1    },    "module_tag": ["default", "handheld"]}```  ### **Module Instances**these represent the ingame on item modules.  they contain different types of data. - key -> this refers to the Item-Modules id in question - children -> this is the child structure, each Module Instance have an infinite amount of children, each uniquely defined by a string-id - data -> an additional string->data map, used for a per-module savedata system.     this is f.e. used to store the material data under the ``miapi:material`` key.Each valid item requires on root module, but each module can as many submodules as it wantsThe Data representation of modules can be easily viewed ingame by using `/data entity @p get SelectedItem` and holding the item in your mainhand.  Example structure of the vanilla wood axe.```json{        "key": "tm_arsenal:handle/tool",        "data": {            "material": "miapi:wood/wood"        },        "child": {            "guard": {                "key": "tm_arsenal:guard/tool_adapter",                "child": {                    "tool_head": {                        "key": "tm_arsenal:tool/axe_front",                        "data": {                            "material": "miapi:wood/wood"                        },                        "child": {                            "tool_back": {                                "key": "tm_arsenal:tool/tool_back",                                "data": {                                    "material": "miapi:wood/wood"                                },                                "child": {}                            }                        }                    }                }            }        }    }```These structures are only needed to be used during Modular Converters or Blueprints, as they contain fully fleshed out modules.
